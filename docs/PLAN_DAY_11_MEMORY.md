# День 11: Модель памяти ассистента (план)

## Модель трёх слоёв


| Слой                      | Содержимое                       | Хранение                                    | Очистка                                                                              |
| ------------------------- | -------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------ |
| **Память диалога**        | Сообщения + стратегия контекста  | Room (messages, summaries, facts, branches) | Удаляется при «Очистить историю»                                                     |
| **Память задачи**         | Данные текущей задачи            | Отдельная таблица agent_task_memories       | **Чистится:** отдельная кнопка в настройках и/или чекбокс в диалоге «Очистить историю» — «Также очистить память задачи» |
| **Долговременная память** | Профиль, решения, знания по чату | Отдельная таблица agent_long_term_memory    | Не удаляется при очистке сессии                                                      |


---

## Основной сценарий работы с памятью

1. **Преднастройка перед стартом диалога**
  Пользователь может заполнить долговременную память и/или память задачи **до первого сообщения**: при открытии экрана агента (пустая история) или через настройки до начала чата.
2. **В любой момент в процессе**
  Редактирование и дополнение долговременной памяти и памяти задач — через Bottom Sheet «Настройки агента» (секции «Долговременная память» и «Память задачи»). Это **основной** способ задать и изменить память.
3. **Long-tap по сообщению (дополнительно)**
  При длинном тапе по сообщению — не сохранять текст сообщения целиком. Вместо этого:
  - запускать **извлечение фактов** из выбранного сообщения (аналогично стратегии Sticky Facts: вызов LLM «извлеки факты»);
  - полученный текст фактов добавлять в выбранный слой: «В долговременную память» или «В память задачи X».

То есть long-tap = «извлечь факты из этого сообщения и сохранить их в выбранный слой», а не «сохранить сообщение как есть».

4. **Консольные команды в поле ввода**
   Если пользователь вводит строку, начинающуюся с специальной команды, запрос **не отправляется в модель**, а выполняется действие над памятью. Примеры:
   - **`/add_task_memory <текст>`** — извлечь факты из `<текст>` и сохранить в **задачу, которая сейчас загружена в диалог**. Если ни одна не загружена — тост «Сначала загрузите задачу», запрос в модель не отправляется.
   - **`/add_long_term <текст>`** — извлечь факты из `<текст>` и добавить в долговременную память (append).
   - **`/help`** (или **`/memory_help`**) — показать список команд в тосте или в диалоге.
   - Опционально: **`/clear_task_memory`** — очистить память задачи.

   Реализация: при нажатии «Отправить» ViewModel проверяет `request.trim()`. Если начинается с `/`, разбирать как команду (парсинг префикса и аргументов), выполнить соответствующее действие (извлечение фактов + сохранение), показать тост «Факты добавлены в …», очистить поле ввода; запрос в агент не отправлять.

## Реализация (кратко)

### 1. Domain

- **SimpleAgent.process(...)** — добавить параметры `longTermMemory: String`, `taskMemory: String?`. В начале промпта блоки «Долговременная память» и «Память текущей задачи» (если есть).

### 2. Data

- **Room, миграция 3→4:** таблицы `agent_long_term_memory` (одна запись на чат), `agent_task_memories` (id, name, content).
- **AgentDialogStorage:** get/save long-term; CRUD по задачам; **clear()** не трогает long-term и task_memories. Метод **clearTaskMemories()** — удаление всех записей из agent_task_memories. Вызов: кнопка в настройках и при подтверждении «Очистить историю» с отмеченным чекбоксом «Также очистить память задачи».
- **ChatRepository:** метод **extractFactsFromMessages(messages: List<AgentMessage>): Result<String>** (или **extractFactsFromText(text: String)** для одного фрагмента) — по аналогии с `extractOrUpdateFacts`, но без текущих фактов: один вызов LLM «извлеки факты из этого фрагмента», возврат текста фактов. Используется при long-tap и при обработке команд `/add_task_memory`, `/add_long_term`.

### 3. ViewModel

- Загрузка long-term и списка задач при открытии экрана; передача longTerm и taskMemory (если задача загружена) в `agent.process`.
- Методы: save/update long-term, saveToTaskMemory(name, content), loadTaskIntoDialog(id), unloadTask, deleteTaskMemory(id), **clearTaskMemories()**.
- **Long-tap:** при выборе «Сохранить в долговременную» / «В память задачи X» — вызвать `repository.extractFactsFromMessages(listOf(selectedMessage))`, при успехе добавить результат к long-term или к выбранной задаче (append/merge).
- **Консольные команды:** при «Отправить» если `request` начинается с `/` — не вызывать `agent.process`. Разбор команды (например `/add_task_memory текст`, `/add_long_term текст`): извлечь факты из аргумента через `extractFactsFromMessages` или метод для одного текста `extractFactsFromText(text)`, сохранить в нужный слой, тост, очистить поле; иначе — обычная отправка в модель.

### 4. UI

- **Основной поток:** в Bottom Sheet «Настройки агента» — секции «Долговременная память» (поле ввода/редактирования) и «Память задачи» (список задач, добавить, загрузить в диалог/отключить, **очистить память задачи**). Преднастройка при пустом чате — те же секции доступны до первого сообщения. При «Очистить историю» — диалог подтверждения с чекбоксом **«Также очистить память задачи»**.
- **Long-tap по сообщению:** контекстное меню «Извлечь факты и сохранить» → подменю «В долговременную память» / «В память задачи: [список]». По выбору — вызов извлечения фактов и добавление в выбранный слой.
- **Команды в поле ввода:** ввод вида `/add_task_memory текст` или `/add_long_term текст` (и при необходимости `/clear_task_memory`, `/help`) — по «Отправить» выполняется только действие с памятью, запрос в модель не уходит. В настройках или по `/help` можно вывести подсказку по формату команд.

### 5. Подключённая задача по ветке (реализовано)

- Для каждой ветки диалога в БД хранится id подключённой задачи (`agent_branches.loadedTaskId`, миграция 4→5). При перезаходе в приложение и при переключении ветки эта задача автоматически подставляется в диалог (если запись задачи не удалена). При подключении/отключении задачи в UI вызывается `saveLoadedTaskIdForBranch(currentBranchId, taskId)`.

### 6. Проверка

- Долговременная переживает «Очистить историю»; память задачи чистится отдельной кнопкой (или опцией).
- Преднастройка: заполнить память до первого сообщения — ответ агента учитывает её.
- Long-tap: сохраняются извлечённые факты, а не полный текст сообщения.
- Команды: ввод `/add_long_term я предпочитаю Kotlin` → факты извлекаются и дополняют долговременную память; сообщение в чат не отправляется.
- Подключённая задача: подключить задачу к диалогу, выйти из экрана и вернуться (или переключить ветку и обратно) — задача снова отображается как подключённая.

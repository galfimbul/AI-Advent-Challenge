# Discussion. Разные способы рассуждения — план реализации

Ветки в проекте называются по дням (например `challenge_day_3`). Планы в `docs/` — по смыслу задачи (здесь: Discussion).

---

## Условие задачи

Взять **одну задачу** (логическую, алгоритмическую или аналитическую) и решить её через API **четырьмя способами**:

1. **Прямой ответ** — без дополнительных инструкций.
2. **Пошагово** — в промпт добавлена инструкция «решай пошагово».
3. **Через свой промпт** — сначала запросить у модели промпт для решения задачи, затем использовать этот промпт для решения.
4. **Группа экспертов** — в промпте заданы роли (аналитик, инженер, критик), получить решение от каждого.

**Результат:** несколько решений одной задачи и их сравнение (отличаются ли ответы, какой способ дал наиболее точный результат).

---

## Варианты реализации в текущем приложении

### Вариант A: Отдельный экран Discussion с четырьмя кнопками

- **Экран:** одно поле ввода задачи + 4 кнопки («Прямой», «Пошагово», «Свой промпт», «Эксперты») + 4 области для ответов (или табы/аккордеон).
- **Поведение:** пользователь вводит задачу, нажимает одну кнопку — выполняется один запрос, результат показывается в соответствующем блоке. Можно запускать все 4 подряд кнопкой «Запустить все».
- **Сравнение:** пятая кнопка «Сравнить» — отправляет все 4 ответа одной запросом в модель с просьбой сравнить и указать наиболее точный способ; результат выводится отдельно. Либо сравнение пользователь делает сам по текстам на экране.
- **Плюсы:** понятно, гибко (можно запускать выборочно). **Минусы:** экран громоздкий при 4 длинных ответах.

### Вариант B: Пошаговый сценарий (wizard)

- Шаг 1: ввод задачи.
- Шаг 2: запрос «прямой ответ», показ результата.
- Шаг 3: запрос «пошагово», показ результата.
- Шаг 4: запрос «свой промпт» (два вызова API: сначала «составь промпт», потом решение по нему), показ результата.
- Шаг 5: запрос «эксперты», показ результата.
- Шаг 6: экран сравнения (все 4 ответа + опционально запрос к модели «сравни и выбери лучший»).
- **Плюсы:** линейный сценарий, не перегруженный экран. **Минусы:** много шагов, нельзя «только способ 3».

### Вариант C: Один экран со списком способов и одной зоной ответа

- Список из 4 способов (карточки или список). Пользователь выбирает способ и нажимает «Решить» — запрос уходит, ответ показывается в одной области внизу. История: под списком — 4 блока (свернутые/развернутые) с последним ответом по каждому способу.
- Кнопка «Запустить все 4» — последовательно 4 запроса, результаты накапливаются в этих блоках. Кнопка «Сравнить» — запрос к модели с текстами 4 ответов.
- **Плюсы:** компактно, всё на одном экране. **Минусы:** при длинных ответах нужна прокрутка/сворачивание.

**Рекомендация:** начать с **варианта A** (отдельный экран с 4 кнопками и 4 областями ответов + кнопка «Запустить все» и «Сравнить»). При необходимости потом можно упростить до C или добавить wizard (B).

## Что изменится, если задать этот вопрос в новом чате в режиме Plan?

- **Разбиение на шаги:** Plan сам предложит порядок (сначала данные/API, потом UI, потом навигация) и зависимости между шагами.
- **Учёт репозитория:** Plan может явно указать «переиспользовать ChatRepository», «добавить методы под 4 способа» и т.д.
- **Чеклисты и подзадачи:** появятся конкретные подзадачи (типа «добавить enum ReasoningMode», «реализовать buildMessages(mode)», «экран DiscussionScreen») с отметкой выполнения.
- **Меньше контекста вручную:** в новом чате нужно будет дать ссылку на этот план (и при необходимости PROJECT.md / ARCHITECTURE.md), чтобы модель не забыла про текущую структуру приложения.

Режим Plan не меняет суть реализации, но структурирует её в последовательность шагов и подзадач, удобную для пошагового выполнения.

### Контекст

- Проект: **AI Advent Challenge**, Android, Kotlin, Compose, OpenAI Chat Completions API.
- Ветка: создать **challenge_day_3** от **challenge_day_2** (ветки — по дням).
- Задача: одна и та же задача решается 4 способами (прямой ответ, пошагово, через свой промпт, группа экспертов), затем сравнение ответов. Экран и классы — Discussion (по смыслу).

### Шаг 1. Данные и API

- В **ChatRepository** (или в отдельном сервисе/use case) добавить поддержку «режимов рассуждения»:
  - **Способ 1 (прямой):** один запрос: `messages = [user: задача]`, без system или нейтральный system.
  - **Способ 2 (пошагово):** один запрос: system или user с инструкцией «решай пошагово», user — задача.
  - **Способ 3 (свой промпт):** два запроса: (1) «Составь промпт для решения такой задачи: \<задача\>» → ответ = промпт; (2) запрос с этим промптом (и задачей) как system или как часть user.
  - **Способ 4 (эксперты):** один запрос: system задаёт роли (аналитик, инженер, критик), user — «Реши задачу, получи ответ от каждого эксперта: \<задача\>».
- Сигнатура может быть вида: `solveWithReasoningMode(task: String, mode: ReasoningMode): Result<ChatResponse>` или 4 отдельные функции. Для способа 3 — два вызова подряд, результат второго считать итогом.
- Переиспользовать существующий `sendMessage` / запрос к API; различаться должны только формируемые `messages` (и при необходимости отключение общего SYSTEM_MESSAGE для Discussion).

### Шаг 2. Модель состояния и ViewModel для Discussion

- Ввести **enum** (или sealed class) с 4 способами: e.g. `Direct`, `StepByStep`, `SelfPrompt`, `Experts`.
- **Состояние экрана Discussion:** текст задачи, по одному полю на каждый способ (текст ответа или null), флаги загрузки по способам, текст сравнения (если делаем запрос «сравни»), ошибка.
- **ViewModel:** методы «запустить способ N», «запустить все 4» (последовательно 4 вызова), «сравнить» (один запрос с 4 текстами ответов и просьбой сравнить и указать наиболее точный). Вызовы к репозиторию/сервису из п.1.

### Шаг 3. UI экрана Discussion

- Один экран: поле ввода задачи, 4 кнопки (по одной на способ) и/или одна кнопка «Запустить все».
- 4 области отображения ответов (подписи: «Прямой ответ», «Пошагово», «Свой промпт», «Эксперты»). При длинных текстах — прокрутка или ограничение высоты с прокруткой.
- Кнопка «Сравнить» активна, когда есть хотя бы 2 ответа; по нажатию — запрос к API с текстами ответов и просьбой сравнить; результат сравнения выводить отдельным блоком под ответами.

### Шаг 4. Навигация

- Из текущего экрана (чат) добавить переход на экран Discussion (кнопка «Обсуждение» или «Способы рассуждения»). И обратно — возврат на чат.
- Вариант: в **MainActivity** по умолчанию показывать экран с выбором «Чат» / «Обсуждение» или нижняя навигация с двумя пунктами. Минимально — одна кнопка на текущем чате «Обсуждение» и на экране Discussion кнопка «Назад» или «К чату».

### Шаг 5. Сравнение

- Реализовать запрос к API: в user (или system) передать текст задачи и 4 ответа с подписями (какой способ); попросить модель сравнить и ответить: отличаются ли ответы, какой способ дал наиболее точный результат. Ответ вывести в блоке «Сравнение».

### Пример формулировок промптов (для реализации)

- **Прямой:** `messages = [ChatMessage(role = "user", content = task)]`.
- **Пошагово:** system = «Решай задачу пошагово.» (или включить в user), user = задача.
- **Свой промпт:** запрос 1 — user = «Составь краткий промпт (инструкцию) для решения следующей задачи. Задача: \<task\>. Выведи только текст промпта.»; запрос 2 — system = ответ_1 (или user = ответ_1 + задача), user = задача.
- **Эксперты:** system = «Ты — группа экспертов: аналитик, инженер и критик. Реши задачу так, чтобы каждый эксперт дал свой ответ: сначала аналитик, затем инженер, затем критик. Подписывай ответы (Аналитик:, Инженер:, Критик:).», user = задача.

# Главный экран приложения — план реализации

Экран-хаб: ASCII-графика на тему AI, название приложения, раскрывающиеся блоки по темам с кнопками перехода на экраны. Заданий будет становиться больше — структура должна легко расширяться.

---

## Цель

- **Главный экран** — стартовая точка приложения (startDestination).
- **Внешний вид:** ASCII-картинка на тему AI → название «Ai Advent Challenge With Love» → несколько раскрывающихся блоков по темам, внутри — кнопки навигации на экраны.
- **Первый блок:** «Промптинг» с кнопками: Чат, Обсуждение (и далее по мере появления экранов).

---

## Шаги реализации

### Шаг 1. Маршруты и навигация

- Добавить маршрут **`home`** (главный экран).
- Сделать **startDestination = "home"** вместо `"chat"`.
- На главном экране не нужна кнопка «Назад» (это корень). Экраны Чат и Обсуждение по кнопке «Назад» возвращают на **home** (popBackStack или navigate("home") с popUpTo).
- Варианты:
  - **A:** При переходе с home на chat/discussion использовать `navigate("chat")` и т.д.; обратно — `popBackStack()`. Тогда в back stack: home → chat.
  - **B:** При возврате явно переходить на home: `navigate("home") { popUpTo("home") { inclusive = true } }` или проще `popBackStack("home", false)`.
- Рекомендация: оставить стандартный `popBackStack()` с экранов чата и Discussion — пользователь вернётся на home.

**Результат шага:** в MainActivity три маршрута: `home` (start), `chat`, `discussion`. Временная заглушка HomeScreen (например, текст "Home" и две кнопки Чат / Обсуждение) для проверки навигации.

---

### Шаг 2. ASCII-графика и название

- **ASCII-арт:** один статический блок текста на тему AI (мозг, робот, нейросеть — компактно, читаемо на телефоне). Хранить как константа в коде или в строковом ресурсе (например `strings.xml` или константа в HomeScreen/отдельном объекте).
- Отображать в `Text(..., font = FontFamily.Monospace)` с подходящим размером, чтобы не занимало полэкрана. Цвет — из темы (onSurface или onSurfaceVariant).
- **Название:** строка **«Ai Advent Challenge With Love»** под (или над) ASCII — отдельный `Text` с `MaterialTheme.typography.headlineMedium` (или headlineSmall), по центру или по ширине.
- Варианты размещения: Column(ASCII → название) или название сверху, затем ASCII. Сверху вниз: название → ASCII — логично как «заголовок приложения», затем визуал.

**Результат шага:** на экране отображаются ASCII-картинка и заголовок приложения.

---

### Шаг 3. Модель данных для блоков и кнопок

- Ввести структуру «секция главного экрана»:
  - **id** (или title) секции;
  - **заголовок** (например «Промптинг»);
  - **список пунктов:** каждый пункт — подпись кнопки + маршрут (или идентификатор экрана).
- Пример в коде (Kotlin):
  - `data class HomeNavItem(val label: String, val route: String)`
  - `data class HomeSection(val title: String, val items: List<HomeNavItem>)`
  - Список секций задать константой (или позже из конфига):  
    `listOf(HomeSection("Промптинг", listOf(HomeNavItem("Чат", "chat"), HomeNavItem("Обсуждение", "discussion"))))`
- Размещение: пакет `ui.home` или общий `domain`/`ui` — по правилу проекта (вспомогательные типы не в репозиториях). Подойдёт, например, `ui.home.HomeScreenState` или отдельный файл `HomeNav.kt` в `ui.home`.

**Результат шага:** есть типы и данные для секций и пунктов навигации; добавление новых тем/кнопок — добавление элементов в список.

---

### Шаг 4. Раскрывающиеся блоки (аккордеон)

- Один блок = заголовок (кликабельный) + содержимое (кнопки). По нажатию на заголовок блок раскрывается или сворачивается.
- Состояние: какие блоки раскрыты. Варианты:
  - **Один открыт:** `expandedSectionId: String?` — при открытии другого предыдущий закрывается (аккордеон).
  - **Несколько открыты:** `Set<String>` или `List<String>` — можно держать открытыми несколько секций.
- Рекомендация: **один открыт** (аккордеон) — меньше скролла, проще на маленьком экране.
- Реализация в Compose:
  - Для анимации раскрытия: `AnimatedVisibility` (или `expandable`-подход) вокруг контента блока; при переключении `expandedSectionId` контент показывается/скрывается.
  - Заголовок: `Row` с иконкой (стрелка вниз/вверх) + `Text(title)`; клик по всей строке переключает `expandedSectionId`.
  - Внутри блока: `Column` с кнопками (`Button` или `OutlinedButton`) — каждая вызывает `onNavigate(route)` (передаётся из HomeScreen в ViewModel или напрямую NavController).
- Передача навигации: в HomeScreen получить `NavController` (или callback `onNavigate: (String) -> Unit` из MainActivity). При нажатии на пункт вызывать `navController.navigate(item.route)`.

**Результат шага:** на главном экране отображаются секции с раскрытием/сворачиванием; внутри первой секции «Промптинг» — кнопки Чат и Обсуждение, ведущие на соответствующие экраны.

---

### Шаг 5. Сборка главного экрана и стиль

- Собрать экран в одном месте: сверху вниз — название приложения, ASCII, затем список секций (например в `LazyColumn` или `Column` с `verticalScroll`).
- Отступы и отступ между секциями задать через `Modifier.padding`, `Arrangement.spacedBy` и т.п., чтобы блоки не слипались.
- Секции оформить карточками (`Card`) или просто фон/разделитель — по вкусу, главное читаемость и соответствие Material 3.
- Проверить поведение на малом экране: скролл всего экрана, ASCII не слишком крупная.

**Результат шага:** главный экран полностью собирается, выглядит аккуратно, все кнопки ведут на нужные экраны.

---

### Шаг 6. (Опционально) Анимация и полировка

- Плавное раскрытие/сворачивание секций: `AnimatedVisibility` с `expandVertically()` / `shrinkVertically()` и, при желании, `fadeIn()` / `fadeOut()`.
- Поворот стрелки при раскрытии: `rotate` в зависимости от `expandedSectionId == section.id`.
- При необходимости — лёгкая анимация появления списка секций (например последовательное появление).

**Результат шага:** главный экран ведёт себя предсказуемо и приятно в использовании.

## Пример ASCII (компактный вариант)

Можно взять за основу и уменьшить/упростить при необходимости:

```
    ___
   /   \
  | o o |
  |  ^  |
  | \_/ |
   \___/
   /AI\
```

Или короткий вариант «мозг/нейросеть»: несколько узлов и связей в 5–7 строках. Имеет смысл подобрать один статичный вариант и положить в константу.

## Расширение в будущем

- Новый экран по заданию → добавить маршрут в NavHost, добавить пункт в нужную секцию (или новую секцию) в списке `HomeSection`.
- Новая тема (не «Промптинг») → добавить новый элемент в список секций с собственным заголовком и списком `HomeNavItem`.

Таким образом главный экран остаётся единой точкой входа, а новые задания превращаются в новые кнопки внутри тем.
